- 状态：Approved system extraction
- 日期：2026-06-20
- 依据：`PRODUCT.md`、`docs/product/ia-v1.md`、现有首页、锁定 `/work` 动效结构、已确认案例详情深浅双主题预览
- 设计原则：只提取已确认规则，不把本文件作为创造新视觉方向的许可

## 1. 固定品牌边界

### 不可变资产

1. 首页现有设计保持不变，包括两张现有图片、前后全屏叠层关系与柔边局部揭示。
2. `/work` 的滚动驱动、空间切换、中央主卡与前后相邻卡片的运动逻辑保持不变。
3. 深浅模式共享同一信息架构、组件尺寸、排版层级和交互状态；主题切换只改变语义颜色与表面材质。
4. Logo 只使用现有 `assets/logo-lockup.svg` 和 `assets/logo-mark.svg`，未经批准不得重绘。

### 产品边界

- 第一版核心是避雷案例、专家点评、学术挑战。
- 首页承担品牌入口，`/work` 承担沉浸式模块入口，内容页承担真实阅读和判断任务。
- 不出现登录、支付、站内上传、聊天、人才市场或 B2B 后台入口。
- 美学引擎只能表达 Coming Soon，不得暗示已经能够上传或交付。

## 2. 品牌人格与语言规则

### Core Attributes

| 属性 | 说明 |
|---|---|
| **克制** | 不用夸张承诺、情绪煽动或装饰性术语替代事实 |
| **学术** | 观点对应病例、证据、判断依据和可复用原则 |
| **精确** | 明确对象、条件、状态和去向，避免含混的功能口号 |

### Brand Personality

| 特质 | We Are | We Are Not |
|---|---|---|
| **克制** | 冷静、节制、以内容为主 | 冷漠、晦涩、故作高深 |
| **学术** | 可追溯、尊重证据、允许不确定性 | 用专家头衔替代论证 |
| **精确** | 具体说明决策节点、风险和行动 | 用“智能赋能”等泛化词包装空内容 |

### 语言基本规则

1. **中文优先。** 主标题、导航、CTA 和状态必须首先使用中文；英文只用于品牌名、文献名或必要医学术语。
2. **判断先于介绍。** 优先写“发生了什么、为何错误、如何修正”，再写平台能力。
3. **一句只承担一个判断。** 短句、主动语态、明确主语；正文每段控制在 2–4 句。
4. **权威必须可追溯。** 专家姓名、专科、点评对象、证据依据同时出现，禁止悬空引语。
5. **风险必须具体。** 使用“高风险”“中风险”并补充风险类型；不只用红色或图标表示。
6. **不夸大确定性。** 使用“提示”“支持”“需要排除”“当前证据不足”，避免把教育内容写成诊断指令。
7. **CTA 描述真实结果。** 使用“查看完整复盘”“进入相关挑战”“申请参与”，避免“立即解锁未来”。

### 推荐词汇

- 决策节点、错误路径、修正复盘、证据依据、可复用原则
- 分诊与鉴别偏差、风险等级、专家点评、关联病例、学术挑战
- 查看、阅读、进入、返回、筛选、申请

### Tone by Context

| 场景 | 语气 | 示例 |
|---|---|---|
| 首页品牌入口 | 简短、定义式 | “让经验、判断与人才找到位置。” |
| 案例列表 | 扫描友好、具体 | “急诊胸痛中的夹层警讯为何被忽略” |
| 案例详情 | 证据导向、承认条件 | “未测量双上肢血压，导致关键分层线索缺失。” |
| 专家点评 | 有判断但不居高临下 | “真正危险的不是缺少检查，而是把最初分类当成结论。” |
| 风险状态 | 直接、不恐吓 | “高风险 · 分诊与鉴别偏差” |
| 空状态 | 解释原因并给出恢复动作 | “当前筛选条件下没有案例。清除筛选后查看全部内容。” |
| 错误状态 | 说明发生了什么和下一步 | “申请未提交，请检查联系方式后重试。” |
| 成功状态 | 简洁、可继续 | “申请已提交。你仍可继续浏览案例。” |

### Forbidden Phrases

- AI 赋能医疗
- 一键诊断
- 权威专家在线坐诊
- 上传病例
- 上传报告
- 立即购买
- 开通会员
- 人才画像
- 人才市场
- 颠覆医疗
- 重塑未来

### 禁止表达与替代

| 禁止表达 | 原因 | 替代方式 |
|---|---|---|
| AI 赋能医疗 | 空泛且容易制造炫技感 | 说明具体能力或删除 |
| 一键诊断 | 超出产品和医学边界 | “查看判断依据” |
| 权威专家在线坐诊 | 暗示真实问诊和咨询 | “阅读专家点评” |
| 上传病例 / 上传报告 | 第一版没有上传能力 | “当前不提供文件上传” |
| 立即购买 / 开通会员 | 第一版没有支付 | 删除 |
| 人才画像 / 人才市场 | 属于延期系统 | 删除 |
| 颠覆医疗 / 重塑未来 | 夸大承诺 | 使用具体可验证结果 |

### 色彩使用

- 浅色主题是临床白/冷灰，不使用米色、奶油色或羊皮纸色。
- 深色主题是近黑绿炭，不使用纯黑作为正文表面。
- 医学青只占界面小比例，用于动作、焦点、当前节点和修正路径，不作大面积装饰。
- 朱红与琥珀只表达风险和错误，不用于普通分类装饰。
- 所有组件必须引用 Semantic 或 Component Token；组件样式中不得直接写 Hex/RGB。

## 4. 字体与排版

### Font Stack

```css
--font-heading: 'Noto Serif SC', 'Songti SC', STSong, serif;
--font-body: 'Inter', 'Noto Sans SC', 'PingFang SC', 'Microsoft YaHei', system-ui, sans-serif;
--font-mono: 'SFMono-Regular', 'Roboto Mono', 'Noto Sans Mono CJK SC', monospace;
```

### 使用规则

- 首页品牌标题沿用现有无衬线设计，不改为衬线体。
- 案例详情主标题可用宋/明体，正文、导航、按钮、筛选器和表单必须使用无衬线体。
- 病例编号、日期、时间和短医学代码可使用等宽字体；不把整页正文设为等宽。
- 正文最低 16px；必要标签最低 14px；12px 只用于非关键 caption。
- 正文行高 1.625，长文阅读行高 1.75，正文行长不超过 65–75ch。
- 显示标题字距不小于 -0.02em，不使用极窄字距。

## 5. Logo 使用规则

### 现有资产

| 资产 | 用途 |
|---|---|
| `assets/logo-lockup.svg` | 浅色背景的网站页头、文档封面、对外正式署名 |
| `assets/logo-mark.svg` | favicon、紧凑导航、移动端和小尺寸品牌识别 |

当前没有获批的反白横版 Logo。深色背景需要完整横版时，应把 `logo-lockup.svg` 放在不透明白色区域内；不得临时反色或重绘。

### 安全区

- 以 Logo mark 宽度的 1/4 作为 `x`。
- Logo 四周至少保留 `x`；不得让导航文字、边框或图片进入安全区。
- 横版 Logo 内部元素比例和间距不得修改。

### 最小尺寸

| 场景 | 最小尺寸 |
|---|---|
| 横版 Logo（数字端） | 140px 宽 |
| Mark（独立展示） | 24px；可交互场景外框至少 44×44px |
| Mark（印刷） | 10mm 宽 |

### 背景与颜色

- `logo-lockup.svg` 只用于白色或临床浅色背景。
- `logo-mark.svg` 可用于浅色或深色背景，但必须保证 mark 外框完整可见。
- 不改变 #1F2524、#F4FBF8、#0F8A82、#B84A3A、#C78A2C 的内部关系。

### 禁止方式

- 不拉伸、压缩、旋转、裁切或重排。
- 不加渐变、描边、外发光、投影或透明度。
- 不把 Logo 放在高噪声图片上；首页使用独立的现有品牌标识方式，保持现状。
- 不把图形中的十字单独提取成通用医院十字。
- 不创建未经批准的反白、单色或动画 Logo。

## 6. 影像、图标与界面材质

### 首页影像

- 只使用现有 `lithos-surface.webp` 与 `lithos-inner.webp`。
- 两图保持同画幅前后叠层，后层通过柔边局部区域揭示。
- 禁止改为单图、轮播、并排对比、硬切圆洞或整屏切换。

### 内容界面

- 使用平面医学档案、表格行、临床决策时间线和学术旁注。
- 表面圆角控制在 4–10px；不使用 24px 以上卡片圆角。
- 默认无阴影；只有浮层可以使用极轻阴影。
- 不使用玻璃卡、连续粒子、扫描纹、宽辉光和装饰性 3D。

### 图标

- 使用简洁线性图标，20px 基准、1.5–2px 线宽。
- 风险图标必须配合文字；装饰图标使用 `aria-hidden`。
- 不创造手绘、卡通或通用医院十字图标体系。

## 7. 可访问性与一致性

- 普通文字对比度至少 4.5:1；大文字和 UI 边界至少 3:1。
- Focus 使用 2px 医学青外环和 2px 背景色 offset，不能只依靠背景变化。
- 所有移动端交互目标至少 44×44 CSS px。
- 深浅主题使用同一组件结构，不因主题改变信息层级或交互位置。
- reduced-motion 规则以 `DESIGN.md` 和 `assets/design-tokens.css` 为准；不允许动画成为内容出现的前提。

## 8. 治理

1. `docs/brand-guidelines.md` 定义品牌人格、Logo 和视觉边界。
2. `assets/design-tokens.json` 是 Token 数据源；`assets/design-tokens.css` 由校验脚本同步生成。
3. `docs/component-specs.md` 定义组件结构、状态和用法。
4. `DESIGN.md` 是面向设计与实现的总入口。
5. 新颜色先进入 Primitive，再映射 Semantic；组件不得直接引用 Primitive 色值。
6. 新组件必须定义 Default、Hover、Focus、Active、Disabled，并通过深浅主题和 reduced-motion 检查。
